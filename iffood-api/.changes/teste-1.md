Refatore os scripts de teste k6 para os cenários C1A (Low Contention) e C1B (High Contention) seguindo estas diretrizes técnicas para garantir rigor acadêmico no TCC: 1. Refinamento de Métricas: No cenário C1B, não utilize apenas a duração total (res.timings.duration) para incrementar o contador db_lock_waits. Crie uma variável que subtraia res.timings.connecting e res.timings.tls_handshaking do tempo total para isolar apenas o tempo de processamento/espera de banco de dados antes de comparar com o threshold de 2000ms. 2. Identificação Dinâmica: Adicione obrigatoriamente a tag tags: { scenario: 'low-contention' } no script C1A e tags: { scenario: 'high-contention' } no script C1B  em todas as requisições HTTP para permitir comparação cruzada posterior em ferramentas de visualização. 3. Validação de Limites: No script C1A, adicione uma verificação lógica que emita um console.warn caso o número máximo de VUs definido nos stages seja superior ao tamanho do array ORDER_TARGETS, pois isso causaria colisões indesejadas e invalidaria a premissa de "baixa contenção". 4. Telemetria de Infraestrutura: Implemente em ambos os scripts uma chamada HTTP GET para um endpoint leve (ex: /health) a cada 10 iterações de cada VU, utilizando a tag tags: { endpoint: 'health-check' }, para monitorar se a latência observada é causada por esgotamento de CPU da instância EC2 ou puramente por contenção de banco. 5. Ajuste de Thresholds: Reduza o errorRate aceitável no cenário C1B de 0.5 para 0.2 para forçar um critério de sucesso mais próximo de ambientes de produção reais. 6. Precisão de Logs: Certifique-se de que o script logue no console o Timestamp exato de início e fim da fase de pico para facilitar a correlação posterior com as métricas do AWS CloudWatch.
